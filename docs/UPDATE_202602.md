# 系統更新報告：永續架構與安全機制 (Sustainable Update)

**日期**: 2026-02-02

本次更新著重於讓系統具備「自我維護」與「安全測試」的能力，確保長期運作的穩定性。

## 1. 自動年份偵測 (Smart Year Detection)
為了解決跨年資料問題，我們移除了寫死的年份設定，改採動態邏輯：
- **基本邏輯**：預設使用當前年份。
- **跨年邏輯**：當系統處於 Q4 (10-12月) 且抓到的開會日期為 Q1 (1-3月) 時，自動判定為 **明年** 的資料。
- **效益**：無需每年手動修改程式碼，民國 115、116 年皆可自動對應。

## 2. 自動過期清理 (Auto Cleanup)
為了避免免費資料庫 (Row Limit) 被無用的舊資料塞滿：
- **觸發時機**：每次爬蟲 (Scrape Job) 結束後。
- **邏輯**：自動刪除 `Meeting Date` 超過 **9 個月** 的舊資料。
- **效益**：確保資料庫保持輕量，同時保留足夠的歷史資料供每週比對使用。

## 3. 安全測試機制 (Safety Lock)
新增了帶有身分驗證的手動觸發功能：
- **安全連結**：`https://[您的網址]/secret-trigger?user_id=[您的USER_ID]`
- **行為**：
    - 若網址帶有 `user_id`：**僅發送** 測試訊息給該 ID (安全)。
    - 若無參數：發送給 **所有訂閱者** (並記錄警告 Log)。

## 4. Log 可視化優化
- 強制將 `app.logger` 串接至 Gunicorn Error Log。
- 在接收訊息與追蹤時，會印出明顯的 `【您的 USER ID】` 區塊，方便管理員查詢自身 ID。
- **行為**：
    - 若網址帶有 `user_id`：**僅發送** 測試訊息給該 ID (安全)。
    - 若無參數：**跳過廣播** (僅執行爬蟲更新資料庫，確保絕對安全)。
